# Genus-2 and Genus-3 Mean-Value Morph Generation

This note records the current reproducible pipeline for genus-2 and genus-3
mean-value-coordinate morphing.

## Overview

For each genus, generate two morphs:

1. **Triangulation morph**: random interior samples plus Bowyer-Watson
   Delaunay-style triangulation.
2. **Cell morph**: a graph obtained by removing selected triangulation edges so
   that the embedded map includes quadrilateral and pentagonal cells.

For each morph, first compute two endpoint embeddings:

- all edge weights equal to `1`,
- half of the edge weights equal to `10`, the other half equal to `1`.

Each endpoint is solved with `poincare_harmonic_map.py`. Mean-value directed
weights are then computed from the two minimized endpoint embeddings and
interpolated frame-by-frame.

## Convexity Check

For cell faces in the Poincare disk, convexity should be checked using
geodesic tangents, not Euclidean straight-line chords.

At each face vertex:

1. Compute the Poincare geodesic tangent direction from the vertex to the
   previous face vertex.
2. Compute the Poincare geodesic tangent direction from the vertex to the next
   face vertex.
3. Use the incoming tangent and outgoing tangent to compute the signed turn
   angle.
4. The face is geodesically convex when every signed turn has the correct
   orientation and the interior angle is less than `pi`.

This matters because a face can look non-convex under straight Euclidean chord
segments while still being convex with respect to Poincare geodesic sides.

## Attached Stars

Mean-value directed weights require each attached star to see all identified
copies under the side-pairing Mobius maps.

In particular, boundary corner vertices in the cut polygon may look valence 2
inside the fundamental domain, but they are not valence 2 on the quotient
surface. The morph script now always adds temporary corner attachment
constraints for mean-value weight computation. It does not change the solver
constraints or the fixed corner vertices.

## Genus-3 Endpoint Generation

The triangulation graph is:

```text
input/example_genus3_klein_quartic_embedded_irregular.json
```

The all-one endpoint was generated with:

```bash
.venv/bin/python poincare_harmonic_map.py \
  input/example_genus3_klein_quartic_embedded_irregular.json \
  --output input/example_genus3_klein_quartic_triangulation_all_1_solution.json \
  --iterations 8000 \
  --step-size 0.006 \
  --tolerance 1e-9
```

The half-10 endpoint input was generated by assigning:

```text
edge_weights[i] = 10, for first half of edges
edge_weights[i] = 1,  for second half of edges
directed_edge_weights[i] = [edge_weights[i], edge_weights[i]]
directed_edge_weight_operator = "energy"
```

Then solved with:

```bash
.venv/bin/python poincare_harmonic_map.py \
  input/example_genus3_klein_quartic_triangulation_half_10.json \
  --output input/example_genus3_klein_quartic_triangulation_half_10_solution.json \
  --iterations 8000 \
  --step-size 0.006 \
  --tolerance 1e-9
```

## Mean-Value Morph: Triangulation

The triangulation mean-value morph was generated with:

```bash
.venv/bin/python make_boundary_weight_morph_mean_value.py \
  --base input/example_genus3_klein_quartic_triangulation_all_1_solution.json \
  --target-embedding input/example_genus3_klein_quartic_triangulation_half_10_solution.json \
  --output-dir boundary_morph_genus3_triangulation_mean_value_all1_to_half10_frames \
  --frames 25 \
  --start-directed-weights mean_value \
  --target-directed-weights mean_value_from_target \
  --normalization unnormalized \
  --directed-edge-weight-operator mean_value \
  --iterations 3000 \
  --step-size 0.001 \
  --tolerance 1e-8 \
  --line-search-objective none \
  --convergence-criterion relative_step \
  --skip-face-orientation-check
```

Viewer:

```bash
.venv/bin/python visualize_morph_frames.py \
  boundary_morph_genus3_triangulation_mean_value_all1_to_half10_frames \
  --output morph_viewer_genus3_triangulation_mean_value_all1_to_half10.html
```

## Notes on Convergence

For directed mean-value weights, the energy is not required to decrease. The
morph script uses:

```text
line_search_objective = none
convergence_criterion = relative_step
```

The stopping criterion is based on the update size rather than energy
minimization.
