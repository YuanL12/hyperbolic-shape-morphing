# Notes on geodesic drawing in `visualize_morph_frames.py`

This note explains the geodesic rendering logic used in:

- `norm2`
- `normalizeAngle`
- `geodesicPoints(a, b)`
- the edge loop inside `draw(index)`

The code lives in the inline JavaScript generated by `visualize_morph_frames.py`.

## Geometric model

The viewer renders edges in the Poincare disk model:

$$
\mathbb{D} = \{(x, y) \in \mathbb{R}^2 : x^2 + y^2 < 1\}.
$$

In this model, geodesics are either:

1. Diameters of the unit disk (Euclidean straight lines through the origin), or
2. Arcs of circles orthogonal to the unit circle.

The function `geodesicPoints(a, b)` returns sampled points on that geodesic for endpoints `a` and `b`.

## Helper functions

### `norm2(p)`

Computes squared Euclidean norm:

$$
\|p\|^2 = p_x^2 + p_y^2.
$$

### `normalizeAngle(delta)`

Wraps an angle difference into:

$$
(-\pi, \pi].
$$

This picks the "short" angular displacement between two angles.

## Why the center equation is linear

For a Euclidean circle with center $c$ and radius $R$ to be orthogonal to the unit circle, one has:

$$
\|c\|^2 = R^2 + 1.
$$

If a point $p$ lies on that geodesic circle, then:

$$
\|p - c\|^2 = R^2.
$$

Substitute $R^2 = \|c\|^2 - 1$:

$$
\|p\|^2 - 2 c \cdot p + \|c\|^2 = \|c\|^2 - 1
$$

so:

$$
2 c \cdot p = \|p\|^2 + 1.
$$

Applying this to both endpoints $a$ and $b$ gives the 2x2 linear system used in code:

$$
\begin{bmatrix}
a_x & a_y \\
b_x & b_y
\end{bmatrix}
c
=
\frac{1}{2}
\begin{bmatrix}
\|a\|^2 + 1 \\
\|b\|^2 + 1
\end{bmatrix}.
$$

The determinant is:

$$
\det = a_x b_y - a_y b_x.
$$

This is exactly `det` in the implementation.

## Step-by-step behavior of `geodesicPoints(a, b)`

### 1) Degenerate / diameter case

If $|\det|$ is near zero, then $a$ and $b$ are nearly collinear with the origin, so the geodesic is a diameter.  
The code returns `[a, b]`, which draws a straight segment.

### 2) Solve for circle center

The code computes:

$$
\mathrm{rhsA} = \frac{\|a\|^2 + 1}{2}, \quad
\mathrm{rhsB} = \frac{\|b\|^2 + 1}{2},
$$

and then (Cramer's rule):

$$
c_x = \frac{\mathrm{rhsA}\, b_y - \mathrm{rhsB}\, a_y}{\det}, \quad
c_y = \frac{a_x\, \mathrm{rhsB} - b_x\, \mathrm{rhsA}}{\det}.
$$

Radius:

$$
R = \|a - c\|.
$$

If radius is invalid or tiny, it falls back to `[a, b]`.

### 3) Get endpoint angles around center

The code parameterizes the circle by angle:

$$
\theta_a = \mathrm{atan2}(a_y - c_y, a_x - c_x), \quad
\theta_b = \mathrm{atan2}(b_y - c_y, b_x - c_x).
$$

Then:

$$
\Delta = \mathrm{normalizeAngle}(\theta_b - \theta_a).
$$

This gives the shorter of the two circle arcs.

### 4) Choose the arc that stays inside the disk

There are two arcs between endpoints. The "short" arc may pass outside the unit disk for this circle.  
The code checks midpoint of the chosen arc:

$$
m = c + R
\begin{bmatrix}
\cos(\theta_a + \Delta/2) \\
\sin(\theta_a + \Delta/2)
\end{bmatrix}.
$$

If $\|m\|^2 > 1 + 10^{-7}$, that arc is outside, so it switches to the other arc by adding/subtracting $2\pi$:

$$
\Delta \leftarrow \Delta \mp 2\pi.
$$

This is the key trick that ensures the rendered arc follows the in-disk geodesic.

### 5) Sample points along the arc

With `samples = 36`, for $k=0,\dots,36$:

$$
t = \frac{k}{36}, \quad
\theta(t) = \theta_a + \Delta t,
$$

$$
p(t) = c + R
\begin{bmatrix}
\cos\theta(t) \\
\sin\theta(t)
\end{bmatrix}.
$$

These sampled points are returned as a polyline approximation of the geodesic.

## How `draw(index)` uses the geodesic points

For each edge `(i, j)`:

1. Fetch endpoint coordinates from `frame.vertices`.
2. Call `geodesicPoints(vertices[i], vertices[j])`.
3. Map each point via `project(...)` from disk coordinates to canvas pixels.
4. Draw with `moveTo` + repeated `lineTo`.

So each hyperbolic edge is rendered as either:

- a straight segment (diameter case), or
- a sampled circular arc orthogonal to the unit circle.

## Practical notes

- `samples = 36` balances speed and smoothness. Increasing it gives smoother arcs.
- The `1e-10` and `1e-7` thresholds handle floating-point noise near degenerate cases and unit-circle boundary checks.
- Because drawing is in canvas Euclidean space, geodesics are approximated by piecewise-linear segments, not analytic SVG arcs.
